# Why｜P1 管理与治理：生命周期闭环 + 前端能力对齐

## 背景与问题

当前系统在“链接/用户/API Key”的治理能力上存在明显缺口：

- **短链生命周期缺失闭环**：缺少删除/归档/恢复等常用动作，导致“仅能启用/禁用”的治理能力过弱，无法满足运营与合规场景（清理、下线、回收、误操作恢复）。
- **用户与 API Key 治理动作不足**：管理端主要停留在创建/列表，缺少禁用/启用、吊销/轮换等常见动作，无法快速处置泄露、离职、风险账号等场景。
- **前端未覆盖后端已支持能力**：短链创建/编辑在后端已支持 `expiresAt/customCode/tags/编辑 originalUrl` 等，但管理页面未提供可用 UI，导致功能“名义可用、实际不可用”。

## 目标（Success Criteria）

1. **短链治理闭环**：
   - 支持归档/恢复（可逆）。
   - 支持删除（不可逆，受限、可审慎执行）。
   - 归档/删除后 Redirect 侧不可再跳转（回源与缓存均不应继续生效）。
2. **用户治理闭环**：
   - 支持禁用/启用用户（管理员权限）。
   - 支持重置密码（管理员权限）。
3. **API Key 治理闭环**：
   - 支持禁用/启用（吊销/恢复）。
   - 支持轮换（生成新 Key，仅返回一次明文；旧 Key 立即失效）。
4. **前端可用性提升**：
   - Links 管理页补齐：创建/编辑时可配置 `expiresAt/customCode/tags/originalUrl/note`，并提供归档/恢复/删除入口（管理员可操作）。

## 非目标（Non-Goals）

- 不引入复杂的“回收站/延迟删除/定时 purge”完整体系（可后续迭代）。
- 不在本次实现“禁用用户后立即使所有已签发 JWT 失效”的全链路会话撤销（若需要可单独设计 token 版本/黑名单）。
- 不新增全量审计日志系统（仅保留必要的服务端日志与幂等约束）。

## 风险与约束

- **数据一致性**：删除短链需要处理关联数据（tags/统计/事件）避免产生大量孤儿数据或误导报表。
- **部署一致性**：Edge 回源查询依赖最新 DB schema（含 `archived_at` 与跳转策略字段），部署时需确保先完成 Flyway 迁移。
- **安全性**：轮换 API Key 必须只回传一次明文，并仅管理员可见。
