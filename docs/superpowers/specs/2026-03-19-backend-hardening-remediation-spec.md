# Backend Hardening Remediation Spec

## Scope

This remediation addresses five concrete backend risks discovered during the March 19, 2026 server review:

1. JWTs remain valid after password reset or logout.
2. Analytics event dedupe identity is derived from client-controlled request IDs.
3. Shortlink writes allow silent lost updates under concurrency.
4. Tenant admins can disable themselves or the last active tenant admin.
5. Core operational tables lack relational constraints, and analytics flush jobs rescan full daily active sets instead of consuming incremental dirty work.

## Required outcomes

### Auth/session invalidation

- Password reset must invalidate previously issued JWTs for that user.
- Logout must revoke the authenticated user's current JWT family, while still clearing cookies when called without a valid authenticated principal.
- JWT validation must reject stale-but-otherwise-valid signatures once the stored user revocation state changes.

### Analytics integrity and scalability

- Analytics visit-event identity persisted to Redis stream / MySQL must be generated by the server, not copied from `X-Request-Id`.
- Redirect traffic should still preserve log correlation via request IDs, but analytics dedupe must not be client-controlled.
- `link_visit_events.request_id` is redefined as a server-owned analytics event identifier. API/log request correlation remains on `ApiResponse.requestId` / logging and is no longer inferred from analytics history rows.
- Stats flush and dimension flush must consume incremental dirty-link markers instead of rescanning all touched links for the day.
- The stats flush and dimension flush pipelines must not fight over the same dirty marker key.
- Dirty-link consumption must be failure-safe: a failed MySQL flush must not permanently lose the pending dirty marker.

### Shortlink write correctness

- Concurrent updates to the same shortlink must not silently overwrite each other.
- Stale writes must fail deterministically and surface as an application-level conflict/business error.
- Archive, restore, update, and delete paths must all participate in the same stale-write protection.

### Tenant admin safety

- A tenant admin must not be able to disable themself through the admin API.
- The last active tenant admin in a tenant must not be disable-able.

### Database integrity

- Live operational relationships should be protected by foreign keys where they do not conflict with product behavior.
- Analytics history retention after shortlink deletion must remain valid, so analytics history tables must not be coupled to `short_links` with restrictive foreign keys.

## Non-goals

- No redesign of the modular monolith structure.
- No introduction of heavyweight session storage or OAuth flows.
- No schema coupling that breaks analytics retention semantics.
